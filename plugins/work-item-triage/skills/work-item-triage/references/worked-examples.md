# Worked cases

Load only the case relevant to a disputed decision. Fixture paths below are relative to the
plugin root; executable expectations are in `tests/expected/`. They illustrate the shared card,
not an additional decision procedure.

1. **Shipped alert fix** — `tests/fixtures/shipped-alert.json`: inspect present logic and linked
   delivery before closing recovered tracking. Keep a separately owned live-verification obligation
   when shipped implementation does not establish customer recovery.

2. **Future database migration** — `tests/fixtures/future-database.json`: only the current database
   is supported. Defer compatibility work until an approved migration dependency changes the need;
   avoid building speculative support because an issue describes a possible future stack.

3. **Upload next action** — `tests/fixtures/upload-next-action.json`: reproduced rejection leaves
   the user without a useful recovery route. Improve current inline feedback/navigation with bounded
   acceptance rather than expanding permanent interface surface.

4. **Invoice consolidation** — `tests/fixtures/invoice-consolidation.json`: consolidate authority,
   matching and preview under an explicit owner while preserving each money invariant and legitimate
   correction path. Required work can remain blocked by a PR review ceiling.

5. **Conditional duplicate** — `tests/fixtures/conditional-successor.json`: an explicit “close after
   successor ships” condition survives duplicate classification. Defer to that dependency instead of
   treating labels or a planned successor as sufficient evidence to close.

6. **Permitted behavior** — `tests/fixtures/owner-permitted-behavior.json`: an attributable later
   ruling permits what an older report called defective. Preserve ownership/rationale and avoid
   rebuilding the rejected intervention; item text alone supplies no new authorization.

7. **Rare irreversible consequence** — `tests/fixtures/rare-high-consequence.json`: a measured low
   incidence still requires a response when the demonstrated consequence violates a commitment.
   Keep the observation denominator/window rather than substituting a discretionary reach score.

8. **Unavailable incidents** — `tests/fixtures/unavailable-incident-data.json`: missing observation
   access supports a bounded verification task. Evidence remains unavailable and has no frequency
   field; absence of data cannot justify describing the defect as rare.

9. **Conditional activation** — `tests/fixtures/conditional-activation.json`: distinguish a merged
   implementation from rollout and observed recovery. Retain the activation/evidence prerequisite;
   source presence alone cannot discharge the live outcome.

10. **Changed owner ruling** — `tests/fixtures/changed-owner-ruling.json`: new attributable authority
    changes a previous assessment. Write a fresh snapshot with supersession provenance, retaining
    the old rationale instead of silently editing history.

The non-code support handoff in `tests/fixtures/github-parity.json` and `tests/fixtures/plane-parity.json`
must yield the same neutral decision. Source unavailability does not invite invented code evidence.
`github-page1.json` and `github-page2-truncated.json` exercise a census spanning pages with an
incomplete continuation; every fetched item receives a disposition while completeness stays limited.
Proposed-item assertions exercise all five filing dispositions through the same validated payload.
